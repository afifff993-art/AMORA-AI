# AMORA architecture

## Layers

1. **Flutter app** (`frontend/`): UI, animations, settings, chat, voice, local
   memory. Talks to the backend over HTTPS/WebSocket.
2. **Kotlin native layer** (`frontend/android/`, from Phase 5): app launching,
   alarms, intents, notifications, via Flutter platform channels. Every command
   goes through `AndroidCommandExecutor`, which validates it and asks for
   confirmation on sensitive actions.
3. **Python FastAPI backend** (`backend/`, from Phase 2): holds the Claude and
   OpenAI API keys, so keys are never inside the APK. Provides chat, search,
   tools, and optional sync.
4. **Storage**: SQLite on the phone (encrypted memory), optional Supabase sync.

## Folder structure (target)

```
amora/
  frontend/lib/{core,screens,widgets,voice,ai,memory,commands,reminders,social_studio,settings}
  frontend/android/            (generated by scripts/setup_android.sh)
  backend/app/{api,services,ai,memory,security,models}
  docs/  scripts/  .github/workflows/
```
Phase 1 contains `core`, `screens`, `widgets`; the others are added in their phase.

## Roadmap

| Phase | Content |
|---|---|
| 1 | Flutter project, theme, home screen, animated AI core, settings |
| 2 | Chat interface + FastAPI backend with Claude/OpenAI |
| 3 | Speech-to-text, female TTS, interrupt, speed/pitch |
| 4 | Encrypted personal memory + conversation history |
| 5 | Kotlin command executor: open apps, settings, camera, share intents |
| 6 | Reminders, alarms, notifications (WorkManager) |
| 7 | Coding, writing, research, calculator tools |
| 8 | Social Media Studio |
| 9 | Plugin architecture + signed updates |
| 10 | Testing, optimization, release APK |

## External services (by phase)

- Phase 2: Anthropic API key and/or OpenAI API key (paid, from their consoles).
- Phase 3: none at first (Android speech engines). Cloud voice is optional.
- Phase 7: a web-search provider key (for example Brave Search or Tavily).
- Phase 8: YouTube Data API (Google Cloud OAuth), Instagram/Facebook Graph API
  (Meta developer app; only Business/Creator accounts can publish).
- Phase 4+: optional Supabase project.

## Android permissions (by phase)

- Phase 1: none.
- Phase 2: INTERNET.
- Phase 3: RECORD_AUDIO.
- Phase 5: none for most intents; QUERY_ALL_PACKAGES or specific `<queries>`
  entries to list/open apps.
- Phase 6: POST_NOTIFICATIONS, SCHEDULE_EXACT_ALARM (alarms/reminders).
- Optional, only with explicit consent: notification listener, accessibility.

## Honest limits

- Wake word ("Hey Amora") only works while the app/foreground service runs.
- AMORA cannot read or send WhatsApp/Instagram messages by itself; it can draft
  and hand text to the official share sheet.
- Rive animations are deferred: the Phase 1 core is drawn with Flutter's
  CustomPainter so it needs no external asset file.
